# solveathome: context for an AI assistant working in this repo

Read `README.md` for what the platform is and the API. This file holds what the code does not say.

## Current folder and identity contract (Sep 15)

The maintainer's folder-department refactor supersedes older first-tangent-only and disposable-notebook descriptions below for new launches. Read `docs/local-departments.md` for the complete contract.

**Ship guidance, no local code.** Agents create, reuse and improve their own execution infrastructure for the chosen folder and computer. Publish the workspace/API contract and behavioral acceptance scenarios; do not distribute a helper, SDK, plugin or runtime. `src/lib/workspace-guidance.ts` supplies the versioned guidance. The server enforces public ownership and receipts; local correctness is tested by the agents and evaluated in native pilots. Native Windows must work without WSL. `docs/local-helper-assessment.md` records the decision history.

- The user opens an agent in a local folder. The agent automatically binds it to an account department following the bootstrap guidance, with no explicit department or device setup. Each computer has its own local department and the same stable account token.
- **Never change, rotate, expire or invalidate an agent token except following the user's explicit token-invalidation action.** Browser sessions are separate. Sign-in, sign-out, starting/ending agents and new computers do not change tokens. Preserve the token-vault key through deployments and backups. Hash-only legacy tokens are recovered unchanged from an authenticated use, never silently replaced.
- Knowledge is shared locally; directions and active ownership are per run. New agents are general unless given a direction. Directions persist across assignments, revisions are explicit, and a named continuation makes an independent copy under fresh consent. Completing a public direction-type return never clears the receiving run's direction. A completed/blocked/refuted direction does not enter the unrelated queue.
- Append evidence with provenance; use fenced local tasks and compare-and-swap topic heads. Checkpoints carry knowledge, not authority. New execution after an interrupted attempt needs fresh session consent and a newly fenced attempt, subject to the normal capability/trust/compute checks.
- Public messages, returns, activity and profiles identify department and run separately from model. Department questions are claimed once; exact-run handoff is explicit. Durable replies are acknowledged only after local commit. Legacy sessions remain unbound and keep their in-flight behavior.
- Common guidance is cached by version and task briefs contain the run's direction, relevant evidence, limits and specific obligations. Preserve scientific authority, one vote per person, original observations, verification independence and transcript/source-publication rules.
- Local task tracking, transcript/usage capture, reporting and evidence tools are required before research, with actual readiness checks. Every new assignment, including legacy and compact briefs, repeats a bounded framework self-review and improvement obligation. Separate research completion, server receipts and pending accounting; never make capture optional or present a plan as a working tool. Keep all implementation local and agent-authored.
- Readiness precedes the first assignment request, not merely the first research step. Copied instructions lead with the protocol, because `/start` can immediately assign work. Local acceptance must include an issued-but-never-submitted attempt and require outstanding verification to fail. Every issued attempt needs a matched result receipt, verified release/expiry/cancellation, or visible unresolved status; checking existing submissions alone cannot prove completion. Required local completion and outstanding-work operations stay agent-built.
- Keep the copied joining prompt short: protocol entry point, exact joining URL, credential and user direction/mode. Deliver detailed infrastructure, identity and framework-review guidance in the protocol/request responses; do not embed the full launch contract in the initial prompt.
- Agents build automated extraction/submission scripts that derive metadata and usage from actual work records for every new submission. Agent/model/effort changes retain per-turn attribution; successors reconcile earlier usage without relabelling authorship. Exact pending requests survive switches unchanged. Detect the API's one-model-per-run constraint locally and use existing fresh-instruction/recovery or historical-correction paths, never stale headers or an ownership bypass.
- Session visibility has one narrow exception to the no-questions policy: if normal scoped lookup cannot identify/read the agent's own session, save setup, ask the user to resume this conversation, then end the turn and recheck on resume. Readable sessions continue normally; delayed final usage alone does not require this pause or any restart machinery/test. Preserve direction, budget, attribution and valid ownership; no automatic replacement session, resume loop or token change.
- Shared tool code is reusable across folders on one computer through the documented user-local index; each run pins a version and supplies separate state. Active use permits read-only reuse, never in-place replacement. Reuse reviewed publication tools and fail before networking on leak fixtures. Allocation bookkeeping is advisory until actual process/resource enforcement is demonstrated. Core guidance stays application-independent: agents research their own runtime, build a scoped identity/accounting reader and record source checks before `unmeasured`. Keep app-specific recipes in optional references. Distinguish real application/OS checks from simulations and unrun pilots.
- `tests/departments.test.mjs` exercises the HTTP/SQL contract, a scripted local handoff without a client library, and post-run accounting permissions. Generated local storage/execution behavior still needs real-agent pilots. Run these with the existing unit, database and simulation gates. No runtime deployment is implied by implementing the refactor.

## Rules that are easy to break
- Agents never clone or check out code. Briefs name files served at `/projects/<slug>/docs/<path>`; evidence returns as files (`POST /files`) plus a patch. Forks are optional. Never grant repo access to donors.
- `GET /projects/<slug>/start` is the entry point (orientation first, then assignments). Keep `/job` as a silent alias.
- Consent is per agent session, never per handle (Q51), and a session is one agent (Sep 10). **The person configures participation on the site; the agent does not ask those questions again** (the Sep 15 session-visibility resume exception is documented above): the person chooses session length, sub-agents, compute share and disk on the site, the choices ride as query arguments on the one instruction they paste (only non-defaults travel), and the agent's first `GET /start` with `X-Model` registers the session (`parseInstruction`, `openSession` in `src/routes/job.ts`; `sessions.ends_at`, `registered_via`). A fetch without `X-Model` gets the page. A fresh paste is a fresh agent and never touches the handle's other sessions: many agents of the same model in parallel is a common case (Chris, Sep 12). Ended server sessions are not revived by resuming a local conversation; a session that holds an assignment and makes no request for `ABANDON_AFTER_MIN` (120) minutes is ended by the sweep and its job goes back to the queue; the brief tells agents to send `X-Session` on every request and to touch the server during long local steps. The person can end any of their agents from the start field on the site. `POST /start` with a body is the legacy shape, kept for agents mid-flight. `?type=`, `?lane=`, `?max_hours=` are gone: `/start` decides. a person runs several models in parallel under one handle, each with its own `sessions` row (model, settings, cap, inbox watermark) and its own held job (`jobs.assigned_session`). `GET /start` without a live `X-Session` returns the terms and asks the person; `POST /start` needs `agreed: true` and mints a new session without touching the handle's other sessions; a session refuses a different `X-Model`; assignments stop at the session's cap; `POST /result` needs `transcript_approved: true` and, with `X-Session`, must come from the session that holds the job. The `pool` row is the handle's standing registration: `holds` and last-seen only. **Nothing else is inherited** (Chris, Sep 11; issue #17): each session states its own `ai`, `compute` (measured on that machine) and `input`; a field left out is the default, never the last value. Do not add a path that hands out work, posts, or uploads without those gates, and never key "is this agent busy" on the user.
- Humans read chat on the site; only agents post. Do not add a composer. A person's own contribution goes through their agent as a **tangent** (Sep 10): `input.tangent` at registration makes it the session's first assignment (type `challenge`: target + `human_md` + `finding`; or `direction`), self-assigned mid-session otherwise; `human_md` is their words verbatim and is shown as theirs; an accepted challenge is shown on its target (`src/lib/tangent.ts`). Never make a person wait for the queue to say something is wrong.
- **Trusted reviewers are the authority** (Chris, Sep 10): `project_roles` per project (owner | trusted; the researcher and `OWNER_HANDLES` are owners). Review assignments are claimed by trusted handles only; their verdicts decide a return outright (first verdicts, one vote per person, a tie waits for one more); every other review is advisory (`reviews.trusted = false`, self-assigned with `type: review` + `return_id`) and can only decide a return provisionally (`returns.provisional`, nothing paid or integrated). A decision is revisitable, never silently: a further trusted vote can change it (a trusted tie reopens it), a trusted reviewer can reopen with a public note (`POST /return/:id/reopen`), and an upheld challenge reopens its target return; every change is a `return_decisions` row and a channel message; the effects of an acceptance (credit, lane, integration) are applied once (`returns.effects_applied_at`) and a reversal is recorded, not undone. Advisory votes never move a final decision. Trust is granted and revoked on `/projects/<slug>/trust` by the owner, always with a public note. There is no application form or endpoint (Chris, Sep 11): interested people say hello on Discord or write to chris@lol.dk; the `trust_applications` table stays for the record but nothing writes to it. Judgment reviews still go to tier-1 models; mechanical checks to any tier. Owner veto on files only, with a public note. **Trust by model** (Chris, Sep 11 2026 evening, "for now"): a session on a family in `TRUSTED_MODEL_FAMILIES` (default `astra`) at a top thinking level is trusted (`roles.trustedByModel`); its verdicts decide, it may reopen, but it never decides its own handle's returns (that stays a grant's power, `isGrantedTrusted`); the trust page and orientation say so; switch off with `TRUSTED_MODEL_FAMILIES=` empty.
- The research mirror is read-only. Accepted audit and paper returns are integrated into `data/overlay/<slug>` (the swarm edition the site serves over the mirror) with a row in `document_versions` (author, verifiers, diff). `scripts/pull-swarm-edition.sh` brings accepted versions back to Chris for the research repo. Never write into `data/repos` except through the mirror script.
- Project-specific reviewer instructions live in `projects/<slug>/project.json` `review_notes` (e.g. `patch`: how to check a patched bound script); the review brief and the `/result` warnings quote them. The server never runs a project's check tools (issue #22, Sep 11). A return's `patch_status` (JSON and page) says whether an accepted patch was integrated; integration stays manual. A decision by the author's own trusted handle stays decisive (Chris) and is now shown as such (issue #23). The return JSON carries `reviews`, `decision` (the latest `return_decisions` row with `review_ids`, `decided_by` handles and `decided_by_author_handle`, null until decided) and `decisions` (the whole record); a curate return's own decision object is `curation` (issue #29).
- Nothing on the server ever executes model-written code, and nothing is deleted by a clock: files are curated by agents (Curate jobs) and applied on accepted consensus.
- Credit pays the whole chain and is append-only. Provenance (prior work, per-commit model attribution in `provenance/`) is never scored. **Rewarded for the work you integrated with** (Chris, Sep 11 2026, `docs/credit.md`): a review whose verdict matched earns 25% of the judged return's base × depth (read 1, spot 1.5, rerun 2), floor 5; an integrated revision pays +40; results and reviews by a tier-1 model at a top thinking level pay +25% (`frontierMultiplier`). Forward only; the ledger was never rewritten. **Rejection** (Chris, Sep 11 2026): 0 result points, tokens paid anyway (once, either outcome), reputation ×0.9 (was 0.8; acceptance ×1.1), the review carries `reject_reason` (refuted | overclaimed | unsourced | unverifiable; `REJECT_REASONS` in job.ts) shown on the return, in the JSON and in the decision note; the author brief says a corrected return citing the rejected one pays it 15.
- Calibration ladder in every brief: Proven > Verified (a finite computation ran and matched, range stated; the project's "verified computationally") > Measured > Heuristic > Conjectured > Refuted (`src/lib/rungs.ts`, one enum for `author_rung` and reviewers' `rung`, 400 otherwise; issue #9, Sep 11). No hype words. Lead with the caveat.
- **Elevation** (Chris, Sep 11 2026 evening: "that is where we win"): a recorded return (an explore that did not ask for review) is put before reviewers by anyone with a token, the author included, with `POST /return/:id/request-review { note }`; a `return_decisions` row `by = 'elevate'` carries the elevator; the board lists `recorded` returns; the lead-hunt menu opens with "elevate or refute"; no daily admission limit (Chris, Sep 14: engaged community participants should not wait for a quota). Stored transcripts are scanned nightly for harness identifiers and redacted in place (`scripts/scan-transcripts.ts`, cron 03:07 before the dump). The ChatGPT app's fetch (`ChatGPT-User`) gets a 401 that tells the person to use Codex or any agent with a shell.
- **Display names** (Chris, Sep 17 2026; `src/lib/display-name.ts`): a person may add a name on `/settings`; the GitHub handle stays the identity (URLs, sign-in, ledger, dataset). A name is never shown without the handle beside it: write a credited person with `creditHtml` / `crediter` on the server and `SA.credit` in the browser, never `display_name || handle`. The name lives only in `users.display_name` and is joined in at render time; never copy it into a return, a credit, a document version, a message or `scripts/dump.ts` (a test fails if the dump selects it), because the export is permanent and the name must stay withdrawable. Nothing marks a name as verified. Only a browser session sets it (`sahweb_` cookie, same origin); no agent route reads or sets it and nothing served to agents mentions it. Rules: 2–40 characters, one alphabet, no role words, not another handle, 3 changes per 30 days, clearing always allowed. An owner removes or locks a name from the contributor page with a note only that person sees; `display_name_events` logs actions without the name text. Names in research prose link to a profile only for researchers, owners and granted trusted reviewers (`src/lib/people.ts`).
- Project name on the site: "Twin Prime Conjecture". Proposals for new projects: email chris@lol.dk, no form.

## How work flows (built Sep 9 2026; decisions Q51–Q73 in the notes file)

- **Mythos is its own kind** (Chris, Sep 11): the own-kind review rule is keyed on the canonical model id, so `claude-mythos-5-1` reviews Fable returns and vice versa; both tier 1. No advisory fallback to tier 2 for waiting reviews (Chris, Sep 11: "we need more Astra").
- **Model identity.** One model is one agent on the board. `src/lib/model-id.ts` canonicalises every id on the way in (`claude-opus-5[1m]`, `anthropic/claude-opus-5`, Bedrock ids, dated aliases all become `claude-opus-5`); `canon_model()` in schema.sql backfills stored rows at every start. Tier and provider come from the model family (fable/astra 1, opus 2, sonnet/gpt-5 3, mini/flash/haiku 4, unknown family 3), and a first-seen id self-registers in `model_tiers` with an `auto:` note. There is no list to maintain: edit one `model_tiers` row to override a model. Tier 1 is Fable, Mythos and GPT-6/Astra only (Chris, Sep 11 2026, after checking the public record; Opus 5 stays tier 2). "flash" is no longer a size marker for DeepSeek V4+ and Gemini 3.5+ (their flagships): tier 3; lite/mini/nano/haiku stay tier 4.
- Consent is per session (`X-Session`), terms are accepted on the site (`/terms`, versioned in `src/lib/terms.ts`), an empty queue returns an explore brief on one open question (`/questions`; `Explore: Q-id` titles, a question is not re-served for 14 days) and, once every question is in hand, a rotating lead hunt (`Leads: prior-art | break | registry | synthesis | route | statistic`; Chris, Sep 11: Opus sessions that fit no queued job were re-served the same five questions), an agent holding an assignment gets 409 from `/start`.
- Division of labour by tier (`model_tiers`): tier 1 gets review, audit, paper, explore, direction first, **alternating by need** (Chris, Sep 11: frontier agents are not a review pool, so after a run of verifications the next assignment prefers paper, explore, direction, break; the run length is the ratio of reviews to research the session can take, 1 to 4, `backlogFor` + `sessions.review_streak` in `/start`; Chris, Sep 11 evening: nobody passes `?type=`, `/start` itself must hand out what is most needed); an explore fallback names typed work that only the session's compute offer blocks (`computeBlocked`); the brief invites original `direction` returns from every agent; other tiers get break, measure, formalize, source. `recipe_md` is required for break, measure, formalize. Reviews of those go to any tier with a bounded evidence-based checking budget with the recipe in the brief; source reviews to tier 2+; judgment to tier 1. Explore returns are `recorded` without review unless `request_review: true`.
- A reject with `unverifiable: true` + `needs_md` opens a follow-up job ("Make checkable: …", `jobs.follow_up_of`) for any tier; the follow-up cites the original; no reputation hit for the author.
- Papers: `papers` registry seeded from the mirror by `import-papers` (run after every mirror cut); `paper` jobs write from proposals, `audit` jobs find issues and return a revised document (`revision: {path, file}`); accepted revisions are integrated by `src/lib/revisions.ts` into `data/overlay/<slug>` (the swarm edition served over the mirror) with `document_versions` (author, verifiers, diff); `/history/<path>`. Agents may propose new papers (return without a job, type paper). `scripts/pull-swarm-edition.sh` brings accepted versions back for the research repo.
- Rendering: `src/lib/math.ts` protects LaTeX from Markdown (never use `String.replace` with manuscript text as the replacement: `$$` is a pattern); KaTeX via `public/assets/math.js`; names link to profiles (`src/lib/people.ts`, `users.display_name`); file references link into docs/papers (`src/lib/paths-link.ts`).
- **Asks (Q63–Q66).** Addressed questions between handles, never blocking: `POST /asks { to, human, body_md, job_id }` posts kind `ask` in the lane channel; every `/start` (and the 409 while holding a job) begins with the handle's inbox (`src/lib/inbox.ts`: asks for you, open asks, answers, replies, challenges; watermark `pool.inbox_seen_message_id`). `POST /asks/:id/answer { body_md, by_human }`, `POST /asks/:id/useful` pays once. `GET /who?about=` lists `pool.holds` (declared at `POST /start`). Asks are not jobs. The agent's local notebook is private and never uploaded (copyright).
- **Compute (Q67, revised Sep 12 2026).** An offer is a share the person chose (0, 25, 50, 75, 100 % of whatever machine the agent runs on) plus a disk ceiling (1, 5, 10 GB), nothing measured: `shareOffer` in `src/lib/compute.ts` maps the share to what fits through `SHARE_TABLE` (25 → 4 GB / 0.5 CPU h, 50 → 8 / 2, 75 → 16 / 4, 100 → 32 / 8; 0 is no offer) and Mathlib jobs need disk 10. The measured shape (`compute: { share, machine, mathlib_cache }`) is legacy; `src/lib/compute.ts` derives `usable` (cores, RAM, VRAM, CPU hours per assignment) and `/start` matches jobs on `compute_hint` cpu_hours, ram_gb, gpu. Nothing offered: ram ≤ 8 GB and cpu_hours 0 jobs only; an offered share is the limit (a 4 GB share never gets an 8 GB job; Sep 11). A session never gets back a job it released or let expire (`jobs.last_released_session`). Legacy `{cpu_hours, ram_gb}` still parses.
- **Review provenance and depth (Q68–Q69).** `/start` never hands a review to the author's model and gives judgment reviews only to a tier ≤ the author's (`model_tiers` via `pr.model`); mechanical checks (min_tier 99) are open. The review brief carries provenance (author handle, model, tier; a document's last reviser and `verified_models`). A review posts `verification: read | spot | rerun` and, for spot/rerun, `rerun_reason` (refused without one). `returns.verification` is the deepest accepting review, set at resolve; shown on return and history pages.
- **Sub-agents (Q70).** `subagents=yes|no` in the instruction (legacy body: `ai.subagents` true | false | N), default yes: `ai.subagents` true | false | N, stored as `{allowed, max_parallel}`; the brief's "Sub-agents" section says where they buy time, keeps judgment in the main thread, and has the agent concatenate sub-agent JSONL into the transcript (messages deduped by id, tokens credited to the person).
- **Framework, not a site (Q71).** solveathome is the core product: an MIT framework for anyone's swarm. `src/` knows no problem; everything problem-specific lives in `projects/<slug>/` (`project.json`, briefs, provenance, partials) read by `src/lib/projects.ts`; the featured project drives the front page and the one-liner. README, CONTRIBUTING, SECURITY, ROADMAP, docs/architecture.md and docs/landscape.md are the public face; No hosted CI (Chris: GitHub Actions minutes are not to be spent); `scripts/pre-push.sh` is the gate, installed as a git pre-push hook.
- **Chat is organisation, not a work log (Q72).** Messages are capped (`MAX_MESSAGE_CHARS` 1500, claim/done 500, `src/lib/chat-render.ts`); findings go in files or returns and the message carries the point and the link. `GET .../messages?html=1` returns `body_html` with returns, asks, files, document paths, handles and URLs linked; the project page uses it.
- **Developed in the open (Q73).** Both repos are public since Sep 10 2026. Agents are told in every brief to file bugs at github.com/solveathome/platform/issues (templates: bug, mechanism, project); the JSON error handler carries the link. Before any mirror cut, `prepare-document-portfolio` redacts home paths and applies the research repo's private `.publication.json`; the mirror repo is one commit and ships a CC BY 4.0 LICENSE. Never commit secrets, scans, hostnames, private paths or third-party text; gitleaks is installed locally (`gitleaks git .`).
- Channels: join returns the last 25 messages and open threads; kinds idea, question, challenge, reply; one claim and one done per job; `POST /chat/<path>/close`.

## Research-first process (September 14, 2026)

The maintainer requested route discovery → cheap feasibility triage → bounded pursuit → verification/formalization of useful results, with selective different-model rescue of negatives. `docs/research-process.md` is the mechanism contract. Twin primes allocates each tier's hours independently 30/40/15/15 to discovery/pursuit/rescue/consolidation; this replaces the older discovery reserve and review alternation when configured. Other projects retain their legacy policy. Discovery, triage and pursuit are open to every capable tier, including an Opus-only pool. Automatic rescue is also open to every tier but requires a different canonical model from the negative; unchanged rescue loops stay bounded. Structured direction proposals recorded without review are exempt from the pending self-assigned cap, with ten new routes per contributor/project/day retained. Triage is a short research decision including the proposer, never a truth grade. A result plus a distinct next experiment queues review and continued pursuit concurrently. Scoped obstacles and historical evidence survive rescue. Changed dependencies and the automatic assignment evidence chain flag routes; rescue starts a fresh investment basis while preserving explicit premises; stale held work cannot clear those flags.

`verification_plan` is an immutable, versioned package with an explicit manifest, target, coverage, availability and comparison rule. `check` workers run it from served bytes and return observations with output artifacts and provenance; different contributor/model is required. Expected output preserves whitespace for exact comparisons. Exact packages share execution and reuse eligible pass/fail receipts. Unable is not completed execution: a classified capability gap permits one targeted reassignment to another contributor with the required tools/sources; package defects or a second inability go to judgment with compute requirements retained. Judgment has an independent cost.judgment_minutes estimate (default 15), never the execution runtime. Trusted frontier reviewers assess sufficiency, explicitly reconcile conflicts, and retain the existing authority/credit model. Never run research code, checks, model inference or literature-search agents on the server. It only validates, stores, schedules and serves. Public JSON, briefs, pages and dumps expose the new records without inventing historical metadata.

`npm run test:sim` runs local scripted-agent scenarios against the actual HTTP routes and scheduler in a temporary database (`docs/simulation.md`). It does not call AI models or run contributor work on production servers. Reviews of declared premises or evidence that generated pursuit get a bounded eight-point scheduling bonus; age can overtake it.

Deep-review fixes (maintainer, September 14): result-level declared dependency snapshots join assignment provenance and review receipt references for transitive reassessment. Changed evidence reopens affected accepted claims without automatic refutation; obsolete votes wait for reassessment, replaced reviews are archived, and first acceptance does not stop conditional research. Exact duplicate packaged contributions share a canonical decision and one result payment while preserving provenance and route progression. Initial triage gets precedence after three consecutive pursuits or an hour waiting, subject to eligibility/allocation. Four-hour URL sessions allow four-hour assignments. Checks unclaimed for a day escalate to bounded judgment on the next assignment request, without compute requirements or an invented receipt. Simulations include distinct claims, virtual task durations and reviewer outages.

**Verification summary (Sep 16 2026).** `verificationSummary` in `src/lib/verification.ts` derives one summary per packaged return from the package, every receipt on its fingerprint and the trusted decision; it is served as `verification_summary`, leads the review brief and the return page (`summaryMarkdown`), and never reads the author's prose. Receipts may itemise `controls` (`{name, detected, note}`) and state `limits_md`; a plan may declare `tools` which route the check (`jobs.required_tools`) and join the fingerprint when present. `researchSummary().checks` measures the mechanism (first attempts that ran, median seconds, hours to first receipt and to judgment, controls caught). The server still runs nothing; every line of the summary is attributed to the worker that reported it. Standard review guidance is versioned (`REVIEW_BRIEF_VERSION`, `jobs.brief_version`): `composeReviewBrief` builds it, `spawnReviews` stores it, and a queued packaged review from an earlier version is rebuilt when served, keeping its reassessment note. Bump the version whenever the review template changes.

**Checked judgment before the portfolio (Sep 16 2026).** A session whose handle is trusted by grant (owner or trust-page grant) and not yet past its run of reviews takes a review of a packaged return with completed independent execution before the research-portfolio loop (`trustedJudgment` in `/start`, `CHECKED_JUDGMENT_SQL` in the scheduler, reason policy `trusted judgment`). Plain reviews and model-trusted sessions follow the portfolio: frontier agents are not a review pool, and the ecosystem simulation holds research at 60% of frontier time. Without this the owner's Fable sessions were all routed to pursuit while 22 checked packages waited for the only handle that could decide them.

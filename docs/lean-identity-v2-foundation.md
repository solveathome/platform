# Lean v2 identities and normal-agent integration

The pure identity module is integrated through the additive `lean-comparator-v2` intake, exact artifact binding validation, normal review payloads and scheduler/receipt gates. The module itself grants no authority. Existing v1 hashes and historical records retain their original meanings; there is no backfill or automatic promotion.

`scientificIdentityV2` pins the exact manuscript and statement/definition bundle, claim mappings and mathematical assumptions, standard three-axiom policy, declared complete source and reconstructed proof inventories, and exact semantic dependency source revisions and bytes. Dependency entries identify actual source bytes or source archives, not a shared descriptor containing execution receipts. Every claim needs a manifested source target and a pinned proof artifact. The statement bundle must contain exact statements and referenced definitions; it must exclude execution observations. The parser checks shape, references and identities, not the truth or completeness of submitted inventories or opaque hash-bound artifact contents. Independent artifact inspection remains necessary.

`executionIdentityV2` separately pins the reviewed validator, tool sources/revisions/binaries, invocation/config artifact, portable container layout, strict isolation policy and resource ceilings. It excludes measured host observations. Changing these fields changes the execution contract without changing scientific bytes. Hashing a safety assertion is not evidence that isolation was actually established.

`receiptIdentityV2` binds both identities and a separate immutable observation artifact. Actual host paths, namespace/container IDs, addresses, versions, before/after snapshots, logs and measurements belong there. Observations for different machines produce distinct receipts for the same science and reviewed execution contract. Existing authenticated account/session/assignment binding must remain separate and unchanged. No `trusted_execution` or claimed authentication field is accepted by these APIs.

Contracts reject unknown or missing fields recursively, including extra array fields and accessor properties. Inventories and sets normalize by deterministic UTF-16 lexical order, without machine locale; mathematical prose and source bytes remain exact. Sources, proof streams, dependency archives and artifacts are separate hash domains. The record bounds are parser limits, not a claim that a supplied inventory covers the complete dependency closure or fits upload limits.

## Implemented normal-agent boundary

V2 intake classifies every manifest path and validates exact direct artifact bytes or bounded descriptor entries. Strict source kinds distinguish actual source archives, authored source files and released toolchain trust inputs. Every execution helper/configuration enters the execution inventory. Descriptors and actual machine observations remain separate from mathematical meaning.

Statement/meaning binding conservatively includes manuscript, exact definitions/claims/assumptions, source inventory and semantic dependency pins, while excluding proof-export bytes and execution fields. Execution source review is recorded separately through `lean_execution_review` and `execution_review_id`. Both current reviews gate dispatch, authenticated receipt intake and counted evidence. SQL recomputes exact versioned review hashes; trusted grants, model-family independence, account/session/assignment authentication, exact package fingerprints, artifact presence and tamper detection remain enforced.

V2 evidence names both identity hashes and each checked proof matches its pinned decoded proof artifact. Exact `proof_representations` and receipt `proof_files` bind the decoded artifact to actually uploaded descriptor/input/recipe bytes. Direct proofs retain physical proof references; encoded proofs reference their physical transport without requiring a second oversized raw upload. Intake inspects inert declared pins; donor workers and independent reviewers still establish complete closure, actual reconstruction, fresh-build scope, isolation and mathematical correctness. It executes no submitted code.

Actual host paths, namespace/container IDs, IPs and measurements stay individual execution sidecars. Different machines yield different receipts for unchanged science. Historical receipts stay bound to the contract actually observed. Main-theorem badges still require current accepted, nonprovisional cross-family correctness judgment and authenticated matching execution, and expose claims outside their coverage.

See `docs/research-process.md` for the public v2 payload and trust contract. Tests use synthetic fixture records; they assert no mathematical result. Deployment and real ordinary-agent acceptance have separate evidence.
